NOT AUTHORIZED: push, merge, deploy, change Vercel or environment settings, change the production model or its settings, build new UI, or fix retrieval/ranking/data-fetch code beyond the label changes in C.7.
This work order overrides AGENTS.md "General Change Policy" items 4-6 for this job only: replacing the interpretation step and removing the code it makes unreachable is explicitly requested.

WHY: The app asks the model for JSON described only in prose (lib/sources/eia/interpret-query.js sends only `model` and `input`; no schema is enforced). It makes the model count character offsets (requestEvidence, interpret-query.js ~line 236). Then it re-interprets the query with the rules engine and lets the rules override the model (interpretQueryWithRules inside validateAiInterpretation and normalizeSubmittedIntent). This job replaces that with one enforced form, plain fact checks, and no second interpreter. A probe also suggests the data-picking step returns wrong or no data for several queries even when the reading is right, so Part A0 measures that first. The result tells the owner what this job can and cannot fix.

PART B. The form (OpenAI Responses API, text.format type json_schema, strict: true)
1. Re-check the official docs (https://developers.openai.com/api/docs/guides/structured-outputs and the gpt-6-luna model page). Confirm Structured Outputs support, that reasoning.effort "low" is accepted, and the schema limits. Record what you read.
2. Build allowed values at runtime from existing sources only: geographies from listApprovedGeographies(); products, activities, sectors and frequencies from phase4-routing-config.json. One code per place: leave code "US" out of the enum (USA covers the United States; including both breaks routing). Define each list once under $defs and reference it with $ref. Each geography enum value carries its name and type, e.g. "GA | Georgia | US state", "GEO | Georgia | country"; code parses the code back out. Do not add a separate geography table to the instructions; the enum labels are the reference. Add a test that builds the real schema and fails if it exceeds any documented limit, counting the way the docs count. Record the counts.
3. Fields (the names may change; the meaning may not):
   - geographies: ordered list of {geography (enum), quoted_words}
   - excluded_geographies: list of {geography (enum), quoted_words}
   - topics: ordered list of {product (enum or null), activity (enum or null), quoted_words}
   - excluded_topics: list of {product (enum or null), activity (enum or null), sector (enum or null), quoted_words}
   - sector: {value (enum or null), quoted_words or null}
   - frequency: {value (enum), explicit (boolean), quoted_words or null}
   - unsupported_words: list of quoted_words the user asked for that none of the fields can hold
   - clarification: {needed (boolean), about (enum: product, geography, activity, frequency, other, or null), options: list of {label (string), value (string)}}
   quoted_words = the words copied exactly as typed, typos included ("icealnd" stays "icealnd"). No character positions anywhere.
4. Model instructions: short and general. State only these meaning rules:
   - bare "energy" means total energy;
   - "gas" without a qualifier is ambiguous: set clarification about product with options natural gas and petroleum (gasoline), leave product null, and keep everything else;
   - Georgia is the country only when another non-US country or an international context is present; otherwise it is the US state;
   - with no stated frequency, use annual with explicit=false;
   - never invent a sector;
   - keep mention order;
   - only explicit exclusions ("not X", "except X", "excluding X", "but not X") go in the excluded lists. Doubt or comparison wording ("not sure", "not convinced") is not an exclusion;
   - a place that cannot be matched to the allowed list needs clarification about geography;
   - ask for clarification only when a required field cannot be determined.
   NO example-phrase lists, NO per-query rules, NO special cases for test queries.

PART C. Plain fact checks (replace the offset contract). Put the locked-form path in a NEW module that imports what it needs, so tests can substitute dependencies.
1. After the model answers, code checks facts only, comparing cleanQueryMechanically() of both sides:
   (a) every quoted_words appears in the raw query (case-insensitive, whitespace-collapsed);
   (b) no geography is both included and excluded;
   (c) clarification about product, activity or frequency: options non-empty and every value valid for that field. About geography or other: options may be empty; any given must be valid;

   (e) unsupported_words non-empty means clarification is required.
   Code does NOT re-interpret meaning and does NOT check spelling.
2. Outcome mapping, no exceptions:
