PART B. Form v2 (Structured Outputs, strict)
1. years: {start (4-digit year or null), end (4-digit year, "latest", or null), quoted_words}. A single year means start = end. "since X" / "from X" means end = "latest". Only an explicit 4-digit year creates a range; words like "lately" or "recent" create none. Code checks: start <= end, both between 1900 and the current year.
2. Each geography item gets is_default (boolean). Vague place words ("many/some/all countries", "worldwide", "globally") do NOT become a place. They become a place clarification (code builds the three buttons). The vague-place rule applies only to countries, never to US states or "the US".
3. Instructions v2 add only these general rules. No example-phrase lists, no per-query rules.

PART C. Never a dead end
1. A failed check never blocks silently. After the existing single Luna re-ask, code builds a question from what failed: missing place -> the three place buttons; unsupported words -> "I couldn't use: <words>. What should I look up?" with free text; unclear product/activity -> buttons from the vocabulary. Always include free text.
2. A clarification with some invalid options keeps the question: drop the invalid options and add free text.
3. The page never sends a blocked or missing form to the search route (fix SearchWorkspace ~42-46).
4. Log every failed check and fallback question (check names, model used, time), with no personal data. This measures whether a second model is worth adding later.
5. When the checks fail, code builds a repaired v2 form: it keeps every field that passed, removes the failing parts, and sets clarification to what failed. The repaired form must pass checkLockedFormV2 on the server, and every later click sends the repaired form. Typed free text starts a new interpretation of '<original query> <typed text>'. Offline test: a failed form, then the fallback question, then a click returns data or a question, never a blocked result.
6. In checkLockedFormV2, geographies may be empty when clarification.about is product or activity. Ask about 'what' before 'where'. After the 'what' answer, if no place is known, ask the place question.
7. Button steps built by code (e.g. C1 -> region list -> data) are authorized; they are not the excluded AI follow-up questions. A second click carries both choices.
